# 阅读位置记忆方案

## 背景

当前用户打开网站时，如果 URL 中没有 `?node=` 参数，会自动跳转到第一个节点（`V01-C01-P0001`）。用户无法在关闭浏览器后回到上次阅读的位置，需要手动从目录中寻找。

## 目标

利用浏览器本地存储，记住用户上次阅读的 **节点 ID** 和 **滚动位置**，在下次打开网站时自动恢复。

## 现有代码分析

### 导航与状态流

```
URL ?node=xxx
    ↓
useNarrative (hooks/useNarrative.ts)
    ├── nodeIdFromUrl = searchParams.get('node')
    ├── 有 node → 加载对应节点
    └── 无 node → 加载第一个节点 (getFirstNodeId)
            ↓
        updateUrl(firstNodeId)  ← 这里是切入点
```

### 滚动状态

`ContentReader` 组件内部已经有 `scrollRef` 和 `handleScroll` 跟踪 `readProgress`（0~1），但仅用于显示进度条，没有向外暴露，也没有持久化。

### 关键改动点

| 文件 | 当前行为 | 需要改动 |
|------|---------|---------|
| `hooks/useNarrative.ts` | 无 node 参数时加载第一个节点 | 优先从 localStorage 恢复 |
| `components/ContentReader.tsx` | 计算 readProgress 用于进度条 | 保存/恢复滚动位置 |
| 新增 `hooks/useReadingProgress.ts` | 不存在 | 封装 localStorage 读写逻辑 |

## 方案设计

### 1. 存储结构

使用 `localStorage`，key 按作品区分，value 为 JSON：

```typescript
// localStorage key: `reading-progress:${workId}`
// 例如: "reading-progress:mao-dazhuan"

interface ReadingProgress {
  /** 当前节点 ID */
  nodeId: string
  /** 正文区域滚动比例 (0~1) */
  scrollRatio: number
  /** 保存时间戳（用于过期/调试） */
  savedAt: number
}
```

**为什么用 `scrollRatio` 而不是 `scrollTop`？**

因为不同屏幕尺寸 / 字号下 `scrollTop` 的绝对值不同，比例值更通用。`ContentReader` 中已经有 `readProgress` 的计算逻辑，可以直接复用。

### 2. 新增 Hook: `useReadingProgress`

```typescript
// hooks/useReadingProgress.ts

const STORAGE_PREFIX = 'reading-progress'

interface ReadingProgress {
  nodeId: string
  scrollRatio: number
  savedAt: number
}

export function useReadingProgress(workId: string | undefined) {
  /** 读取保存的进度 */
  function load(): ReadingProgress | null

  /** 保存进度（节流，≤ 2秒一次） */
  function save(nodeId: string, scrollRatio: number): void

  /** 清除进度 */
  function clear(): void

  return { load, save, clear }
}
```

核心逻辑：
- `load()`：从 `localStorage` 读取并 JSON.parse，捕获异常返回 null
- `save()`：内置节流（throttle），避免滚动事件频繁写入。每次节点切换时立即保存一次，滚动过程中最多 2 秒保存一次
- `clear()`：删除对应 key（可用于"重新开始"功能）

#### SSR / 无 `window` 环境兼容

Next.js App Router 下即使上层组件是 Client Component，逻辑上也建议在 storage 层做“硬防”：

- 任何读写前先判断 `typeof window === 'undefined'`，在服务端直接返回 `null` / noop。
- `localStorage` 访问统一 `try-catch`，避免隐私模式、禁用存储、容量满导致运行时异常。

### 3. 改动: `useNarrative` — 恢复节点

在 `useNarrative.ts` 中，当 URL 没有 `?node` 且 `work` 已加载时，当前逻辑：

```typescript
// 现有代码 (第 114-130 行)
useEffect(() => {
  if (nodeIdFromUrl || !work) return
  async function loadFirstNode() {
    const firstNodeId = await getFirstNodeId()
    if (firstNodeId) updateUrl(firstNodeId)
  }
  loadFirstNode()
}, [nodeIdFromUrl, work, updateUrl])
```

改为：

```typescript
useEffect(() => {
  if (nodeIdFromUrl || !work) return
  async function loadInitialNode() {
    // 1. 尝试从 localStorage 恢复
    const saved = readingProgress.load()
    if (saved?.nodeId) {
      const node = await getNodeById(saved.nodeId)
      if (node) {
        updateUrl(saved.nodeId)
        return
      }
      // 节点不存在（可能内容已更新），清除无效记录
      readingProgress.clear()
    }
    // 2. 兜底：跳转到第一个节点
    const firstNodeId = await getFirstNodeId()
    if (firstNodeId) updateUrl(firstNodeId)
  }
  loadInitialNode()
}, [nodeIdFromUrl, work, updateUrl])
```

**规则**：URL 参数 > localStorage > 第一个节点。这确保了分享链接不会被本地进度覆盖。

### 4. 改动: `ContentReader` — 保存/恢复滚动位置

#### 保存滚动位置

在现有的 `handleScroll` 中增加保存逻辑（通过 props 回调向上传递）：

```typescript
// ContentReader.tsx
interface ContentReaderProps {
  // ...现有 props
  onScrollProgress?: (ratio: number) => void  // 新增
}

const handleScroll = useCallback(() => {
  const el = scrollRef.current
  if (!el) return
  const { scrollTop, scrollHeight, clientHeight } = el
  const max = scrollHeight - clientHeight
  const ratio = max > 0 ? Math.min(scrollTop / max, 1) : 0
  setReadProgress(ratio)
  onScrollProgress?.(ratio)           // 新增：向上传递
}, [onScrollProgress])
```

#### 恢复滚动位置

节点加载完成后，如果有保存的 scrollRatio，恢复滚动位置：

```typescript
// ContentReader.tsx
interface ContentReaderProps {
  // ...现有 props
  initialScrollRatio?: number  // 新增
}

// 节点内容渲染后恢复滚动位置
useEffect(() => {
  if (initialScrollRatio == null || initialScrollRatio <= 0) return
  const el = scrollRef.current
  if (!el) return

  // 使用 requestAnimationFrame 确保 DOM 已渲染
  requestAnimationFrame(() => {
    const max = el.scrollHeight - el.clientHeight
    if (max > 0) {
      el.scrollTop = max * initialScrollRatio
    }
  })
}, [node?.id, initialScrollRatio])
```

#### 防“恢复时机漂移”（推荐）

仅一次 `requestAnimationFrame` 有时不够稳（字体加载、图片/媒体加载、MDX 组件异步渲染会改变 `scrollHeight`），建议增强为：

- **双 raf**：`requestAnimationFrame(() => requestAnimationFrame(restore))`，提高“布局已稳定”的概率
- **一次性 ResizeObserver**：在恢复后短时间内（或一次回调内）监听内容区尺寸变化，再补一次 restore（然后立刻断开），避免高度变化导致位置偏移
- **上报恢复完成**：新增 `onRestoreDone?: () => void`，让上层在“滚动已恢复”之后再开启保存逻辑（见下一节竞态）

### 5. 改动: `ReaderLayout` — 串联保存与恢复

在 `ReaderLayout` 中将 hook 串联起来：

```typescript
// ReaderLayout.tsx
const { load, save } = useReadingProgress(work?.id)

// 保存：节点切换时
useEffect(() => {
  if (currentNode?.id) {
    save(currentNode.id, 0)  // 节点切换，重置 scroll 为 0
  }
}, [currentNode?.id])

// 保存：滚动时（通过 ContentReader 回调）
const handleScrollProgress = useCallback((ratio: number) => {
  if (currentNode?.id) {
    save(currentNode.id, ratio)  // 内部已节流
  }
}, [currentNode?.id, save])

// 恢复：初次加载时的 scrollRatio
const [initialScrollRatio, setInitialScrollRatio] = useState<number | undefined>()
useEffect(() => {
  const saved = load()
  if (saved && saved.nodeId === currentNode?.id) {
    setInitialScrollRatio(saved.scrollRatio)
  }
}, [currentNode?.id])

// 传递给 ContentReader
<ContentReader
  ...
  onScrollProgress={handleScrollProgress}
  initialScrollRatio={initialScrollRatio}
/>
```

#### 防“首屏恢复 vs 保存 0 覆盖”的竞态（必须加）

上面示例里“节点切换立刻 `save(nodeId, 0)`”在**首屏恢复**时会产生竞态：\n
如果 `useNarrative` 通过 localStorage 恢复到某节点，`ReaderLayout` 的 effect 可能先执行 `save(nodeId, 0)`，把原本保存的 `scrollRatio>0` 覆盖掉，导致下次无法准确恢复。

推荐改法（两种任选其一，A 更直接）：

- **A. 恢复阶段禁写（推荐）**：\n
  - `ReaderLayout` 维护 `isRestoringRef` / `isRestoring` 状态。\n
  - 当判定“本次进入是恢复流程且 saved.nodeId === currentNode.id 且 saved.scrollRatio>0”时，先把 `isRestoring=true`。\n
  - `ContentReader` 恢复滚动后触发 `onRestoreDone()`，上层再把 `isRestoring=false`。\n
  - 在 `isRestoring` 为 true 时：\n
    - **禁止** `save(nodeId, 0)`\n
    - **禁止** 响应首轮滚动事件写入（因为程序性设置 `scrollTop` 也会触发 scroll）

- **B. 不在节点切换时写 0**：\n
  - 仅在滚动回调里保存（节流后）。\n
  - 节点切换后的初始值天然是 0（未滚动），无需强制写入。\n
  - 如果业务一定要记录“打开即 0”，可以在用户首次滚动前不写，或者在“用户主动点击切换节点”时写（区分首屏恢复）。

## 数据流总览

```
┌─────────────────────────────────────────────────────────────────┐
│  用户打开网站                                                     │
│                                                                   │
│  URL 有 ?node=xxx?          ─── 是 ──→ 加载该节点                 │
│         │                                                         │
│        否                                                         │
│         ↓                                                         │
│  localStorage 有记录?       ─── 是 ──→ 验证节点存在 → 恢复节点     │
│         │                                  │                      │
│        否                              scrollRatio > 0?           │
│         ↓                                  │                      │
│  加载第一个节点                          是 → 恢复滚动位置          │
│                                                                   │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│  用户阅读过程中                                                   │
│                                                                   │
│  切换节点 ──→ save(nodeId, 0)                                     │
│  滚动正文 ──→ save(nodeId, scrollRatio)  [节流 2s]                │
│  关闭浏览器 ──→ localStorage 已持久化，无需额外处理                 │
│                                                                   │
└─────────────────────────────────────────────────────────────────┘
```

## 边界情况处理

| 场景 | 处理方式 |
|------|---------|
| localStorage 被禁用/满 | `try-catch` 包裹所有操作，静默失败 |
| SSR / 无 window 环境 | storage 层 `typeof window === 'undefined'` 直接返回 `null` / noop |
| 存储的节点已被删除 | `getNodeById` 返回 null 时，清除记录，回退到第一个节点 |
| URL 参数和 localStorage 冲突 | URL 参数优先（支持分享链接） |
| 多个 tab 同时打开 | 各 tab 独立写入，后写的覆盖先写的（单作品场景可接受） |
| 首屏恢复与“保存 0”覆盖竞态 | 恢复阶段禁写（或不在节点切换时写 0），程序性滚动触发的 scroll 也要忽略 |
| 内容更新导致 scrollRatio 偏移 | 比例恢复天然比绝对值更健壮；小幅内容变动影响可忽略 |
| 滚动恢复时机漂移（高度后续变化） | 双 raf + 一次性 ResizeObserver 补偿恢复；必要时增加最大重试次数/超时 |
| 首次访问无记录 | `load()` 返回 null，走原有逻辑 |
